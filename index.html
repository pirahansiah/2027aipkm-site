02 / Why it rots

Four failures that cost engineering weeks

SymptomWhat it actually costs
Eval tables live in a Slack threadThe next model decision is made on memory. Nobody can reproduce last quarter's number.
Prompts in prompts.py as v2_final_FINALYou cannot say which prompt produced the current quality. Rollback is guesswork.
ADRs written once, never revisitedA 2023 decision quietly contradicts the 2026 architecture. New joiners implement the wrong one.
Onboarding by archaeologyThree weeks of asking people. Each answer lives in one head, unsearchable.

Wikis fail for a structural reason: a wiki page has no owner, no diff, no review and no date. A folder in the repo has all four, and can fail a pull request.

04 / Commands

Six commands. That is the whole interface.

pkm.py init DIRscaffold the sections and templates
pkm.py new TYPE "Title"next numbered note from the template
pkm.py indexbuild the search index
pkm.py find "query" --jsonBM25 ranking; JSON for agents and CI
pkm.py lint --max-age-days 120fields, links, staleness; exits 1 on errors
pkm.py statuscounts by type, owners, stale docs

README.md and 90-archive/ are documentation, not records, and are skipped. Rules are ~90 lines of Python you can read and edit in one sitting.

06 / Fit

Buy this if / don't buy this if

Buy this if

  • You have 5–30 engineers and 1–4 models in production.
  • You already do code review, and you would review a decision the same way.
  • You want the knowledge to leave with the repo, not with a SaaS contract.
  • You have been burned by a model card that was two versions out of date.
  • You are fine with markdown and a terminal — that is the whole UX.

Don't buy this if

  • You want a web app with a graph view. This has no UI.
  • You want semantic search. This is BM25; paraphrase queries rank worse and I say so.
  • You are a solo note-taking hobbyist. A vault product will look nicer.
  • You need SSO, permissions or per-page sharing. Git is the permission model.
  • You need it on Windows today. It should run; I have not verified it.

08 / FAQ

Questions worth asking

Why not just a wiki page per decision?

A wiki page has no owner field, no diff review, no date and no failing state. This has all four because it is a file in the repo. That is the entire argument, and it is measurable: run lint on a wiki export and count how many pages have an owner.

Do I need a model or a GPU?

No. There is no model in this product. Search is BM25 over markdown, the linter is regex and frontmatter. Nothing is summarised automatically, which is why nothing is hallucinated into your knowledge base.

How does it compare to an Obsidian or Notion vault product?

Those are personal note systems that happen to hold documents. This is a team record system that happens to use markdown. Different buyer, different failure mode: they optimise for capture, this optimises for review and decay.

Can it work with my existing docs?

Yes — markdown files with the required frontmatter. Run pkm.py init, move files into the sections, add owner/created/updated, then let lint tell you what is still incomplete. Expect half a day for a 100-file repo.

What happens when I stop paying?

Nothing stops working. There is no licence server. The CLI is MIT-licensed; the templates are covered by the purchase. You simply stop receiving updates after 12 months.

Is the search any good?

On the bundled example it ranks the right note first for keyword-shaped questions and second for paraphrase ("why did we drop embeddings" returns the eval first, the decision second). It is lexical, it is fast and it needs no index server. It will not beat a vector store on fuzzy recall, and no page should tell you otherwise.
